# 종키(Jongky) AMR — URDF 전달 문서

## 사용법

```bash
# 1) 워크스페이스에 배치
mkdir -p ~/jongky_ws/src
cp -r jongky_description ~/jongky_ws/src/

# 2) 빌드
cd ~/jongky_ws
colcon build --symlink-install
source install/setup.bash

# 3) RViz에서 확인 (로봇 없이 됨)
ros2 launch jongky_description view_robot.launch.py
```

슬라이더 창이 뜨면 바퀴를 돌려볼 수 있습니다.

## 규약

- 좌표: **+X 전진 / +Y 좌 / +Z 상** (ROS REP-103)
- 메시 단위: **mm** → URDF에서 `scale="0.001 0.001 0.001"` 적용
- `base_link` 원점 = 양쪽 구동 바퀴 축의 정중앙
- `base_footprint` = 구동 바퀴 접지면 (base_link보다 33.5mm 아래)

## 확정된 실측값

| 항목 | 값 |
|---|---|
| 구동 바퀴 반지름 | 33.5 mm |
| 구동 바퀴 폭 | **24.5 mm** (실측. 메시는 27) |
| 휠 트레드 (wheel_separation) | **116.25 mm** (실측 3개 교차검증. 회전 시험으로 최종 확정) |
| 캐스터 반지름 | 12.5 mm |
| 캐스터 위치 | X −125.23, Y ±28.00 |
| 판 (plate) | **148 × 228 mm** (공식 도면) |
| 로봇 전체 질량 | **2.603 kg** (저울) |

### 메시는 검증됐다

`base_link.stl`을 실물·공식 도면과 대조한 결과 전 항목이 맞았다.

| 항목 | 메시 | 대조값 |
|---|---|---|
| 판 폭 | 148.0~148.3 | 공식 도면 148 |
| 판 길이 | 229.1 | 공식 도면 228 |
| 전체 길이 | 249.5 | 실측 245~250 |
| 캐스터 지름 | 25.01 | 실측 반지름 12.5 |
| 후방 카메라 높이 | 바닥 138.9 | 실측 130~150 |

따라서 **치수가 애매하면 메시를 기준으로 삼는다.** 줄자보다 정확하다.

### 폭은 높이·위치마다 다르다 — 재는 자리를 조심할 것

| 부위 | 바닥에서 높이 | 폭 |
|---|---|---|
| 모터 (좌우 돌출) | 29 ~ 37 mm | 119.8 mm |
| 판 (plate) | 101 ~ 125, 181 ~ 213 mm | **148.3 mm** |
| 아스트라 카메라 | 189 ~ 213 mm | 164.9 mm |
| 라이다 | 229 mm 이상 | 약 55 mm |

예전 문서의 "차체 실제 폭 164.89"는 가장 넓은 한 점, 즉 아스트라
카메라를 적은 것이다. 차체 폭이 아니다.

**판은 네 모서리가 모따기되어 있다.** 가운데는 148이지만 앞뒤 끝에서
139.7까지 좁아진다. 앞모서리 근처에 자를 대면 135쯤 나오므로, 폭을
잴 때는 반드시 판 가운데(x −140 ~ +50)를 재야 한다. 실제로 이 함정에
한 번 빠져서 "판이 135"라는 잘못된 결론을 냈다가 공식 도면으로
바로잡았다.

구동 바퀴 바깥면 ±73.67은 판 가장자리 ±74.1과 사실상 나란하다.

## 링크 구조

```
base_footprint
└── base_link              메시 1개 (판·보드·배터리·디스플레이·캐스터 전부)
    ├── l_wheel            continuous, axis (0,1,0)
    ├── r_wheel            continuous, axis (0,1,0)
    ├── laser              RPLIDAR
    ├── camera_link        Astra 뎁스
    ├── rear_camera_link   IMX219
    ├── tof_l_link         TOF400F 좌
    ├── tof_r_link         TOF400F 우
    └── imu_link           야붐 보드 내장
```

## 설계 결정 사항

**콜리전은 메시가 아니라 primitive입니다.**
- 차체: 박스 1개 (249.5 × 280.1 × 246.0, 중심 z = 114.5)
- 캐스터: 구슬 2개 (반지름 12.5)
- 구동 바퀴: 구슬 2개 (반지름 33.5)

바퀴 콜리전을 원통이 아닌 구슬로 한 이유: 원통은 바닥과 선으로 접촉해
접촉점이 프레임마다 흔들리며 차체가 진동합니다. 구슬은 항상 한 점으로
닿아 안정적이고, 지름이 같으므로 굴러간 거리는 동일합니다.

**콜리전 박스 폭 280mm는 의도된 값입니다.**
실제 차체 폭은 164.89mm이지만, 판 사이로 배선이 삐져나오는 것을 감안한
마진입니다. 좁은 통로 통과가 문제되면 `body_wid` 하나만 줄이면 됩니다.

**캐스터는 별도 링크가 아닙니다.**
스위블 관절을 만들면 물리 엔진에서 불안정 요소가 되므로, `base_link`의
콜리전 구슬 2개로만 존재합니다. 마찰 계수를 낮게(0.1 수준) 주십시오.

**좌우 바퀴는 같은 메시 1개를 공용합니다.**
우측은 `<visual><origin rpy>`에서만 180도 반전합니다.
**joint의 rpy는 좌우 모두 0입니다** — 여기에 180도를 주면 axis까지
뒤집혀 오른쪽 바퀴가 반대로 돌고 오도메트리 부호가 반전됩니다.

## 아직 추정값 (실측 후 교체 필요)

`urdf/jongky.urdf.xacro` 상단 `<xacro:property>` 블록만 고치면 됩니다.

| 항목 | 현재 | 비고 |
|---|---|---|
| laser_x / laser_z | 0.01174 / 0.21925 | 스캔 평면 중심 |
| **라이다 yaw** | `${pi}` (적용됨) | 커넥터가 뒤를 향하는 장착 기준. RViz에서 앞쪽 벽이 −X에 찍히면 0으로 되돌릴 것 |
| camera_* | 메시에서 확정 | 아스트라 앞면 73.4 뒤, 바닥 199.1 |
| rear_camera_* | 메시에서 확정 | 뒷면 −176.1 앞, 바닥 138.9 (실측 130~150과 일치) |
| tof_* | 실측 반영 (±5mm) | 근거리 바닥 감지용. pitch 25 / yaw 5, 아래 참조 |
| imu_* | 추정 | 야붐 보드 IMU 칩 위치 |
| body_mass / wheel_mass | 2.503 / 0.05 kg | 전체 2.603 kg 실측. 바퀴는 추정, 몸통이 나머지 |

## 트레드 116.25 — 실측 채택, 회전 시험 남음

실측 3개가 대수적으로 서로 검증된다.

| 측정 | 값 |
|---|---|
| 바퀴 바깥면 간격 | 140 |
| 바퀴 안쪽면 간격 | 92.5 |
| 바퀴 폭 (직접) | 24~25 |

`(140 − 92.5)/2 = 23.75` 로 직접 잰 폭 24~25와 맞아떨어진다.
따라서 `트레드 = (140 + 92.5)/2 = **116.25**`.

`wheel.stl`은 폭 27 / 트레드 120.32로 어느 실측과도 맞지 않는다.
**지금까지 검증된 메시는 `base_link.stl`이고**(판 148×228, 전체 길이
249.5, 캐스터 25.0, 후방 카메라 높이 138.9), `wheel.stl`은 반지름
33.5 외에 대조된 적이 없다. 별개 파일이므로 이것만 다른 바퀴일 수 있다.

**비주얼 메시는 여전히 폭 27짜리 바퀴다.** RViz에서 2.5mm 두껍게
보이는 것뿐이고 좌표·물리에는 영향이 없다.

### 최종 확정은 제자리 회전 시험

자로 잰 건 기하학적 값이다. 타이어가 눌리면서 생기는 실효 트레드는
자로 못 재므로 실차로 잡아야 한다. **트레드 1mm = 오도메트리 회전 0.9%.**

1. 바닥에 로봇 정면 방향을 표시하고 제자리에서 **10바퀴** 회전시킨다.
2. `/odom` yaw 누적값과 실제 3600°를 비교한다.
3. `새 트레드 = 116.25 × (오도메트리 각 / 3600)`
4. 시계/반시계 양방향으로 하고 평균 낸다.

## 실행 인자

```bash
ros2 launch jongky_description view_robot.launch.py
# xacro 인자: cam_tilt_deg, tof_pitch_deg, tof_yaw_deg
```

카메라·TOF 각도는 파일을 고치지 않고 실행 시 바꿀 수 있습니다.

| 인자 | 상태 |
|---|---|
| `cam_tilt_deg` / `tof_pitch_deg` / `tof_yaw_deg` | 동작함 |
| `is_sim` | **미배선 — 자리만 잡아둔 인자** |
| `namespace` | **미배선 — 자리만 잡아둔 인자** |

### is_sim / namespace 에 대하여

두 인자는 `robot.urdf.xacro`에서 선언되어 `insert_robot` 매크로까지
전달되지만 **본문에서 한 번도 참조되지 않습니다.** 지금은 `is_sim:=true`를
넘겨도 출력 URDF가 한 글자도 달라지지 않습니다. 시뮬레이터 연동 시
채워 넣을 자리로 남겨둔 것이며, 각각 아래 작업이 필요합니다.

**Gazebo (`is_sim:=true` 분기 필요)**
- `<ros2_control>` 블록: `gz_ros2_control/GazeboSimSystem` 하드웨어,
  `l_wheel_joint`/`r_wheel_joint`에 velocity 커맨드 + position/velocity 상태
- `<gazebo>` 플러그인: `gz_ros2_control` + 컨트롤러 yaml 경로
- `diff_drive_controller` 파라미터: `wheel_separation: 0.12032`,
  `wheel_radius: 0.0335` (아래 실측표 값 그대로)
- `<gazebo reference="base_link">` 마찰: 캐스터 구슬 영역은 `mu` 0.1 수준
- 라이다/IMU 센서 플러그인

**Isaac Sim**
- URDF Importer는 `<gazebo>` 태그를 그냥 무시하므로 위 블록이 있어도
  무해합니다. 별도 태그 없이 이 URDF를 그대로 임포트하면 됩니다.
- 대신 콜리전 primitive와 관성 텐서를 그대로 신뢰하므로, 아래
  "알려진 사항"의 콜리전 박스 하단 규칙을 반드시 지켜야 합니다.
- continuous 조인트에 `<dynamics damping/friction>`이 없어 임포트 후
  기본값이 들어갑니다. 필요하면 URDF 쪽에 명시하십시오.

**namespace** — 멀티로봇을 하려면 링크·조인트 이름 접두사로 적용해야
합니다. 프레임 이름이 전부 바뀌므로 RViz·네비게이션 설정을 함께
고쳐야 하고, 빈 문자열일 때 현재와 동일한 출력이 나오는지 확인이
필요합니다.

## 알려진 사항

- 캐스터 접지면이 구동 바퀴보다 0.85mm 낮습니다. URDF에서는 캐스터 구슬
  중심 z를 계산값으로 두어 네 접지점이 한 평면에 놓이도록 처리했습니다.
- `base_link.stl` 하단이 z = −34.35mm까지 내려가는 것은 캐스터 때문이며
  정상입니다. **다만 콜리전 박스 하단은 이 값을 쓰면 안 됩니다.** 그대로
  쓰면 박스 바닥이 접지면(−33.5mm)보다 아래로 내려가 바퀴·캐스터 구슬이
  전부 박스 안에 파묻히고, 로봇이 바퀴가 아닌 차체로 바닥에 얹힙니다.
  현재는 박스 하단을 캐스터 구슬 상단(−8.5mm)에 맞춰 놓았습니다.
- 관성 계산에는 마진 포함된 `body_wid`(280) 대신 실제 폭
  `body_wid_real`(164.89)을 씁니다. 콜리전 치수를 관성에 그대로 넣으면
  izz가 1.6배로 부풀어 회전이 둔해집니다.
- 바퀴 `<inertial>`의 `rpy`가 `${pi/2} 0 0`인 것은 `cylinder_inertia`가
  z축 회전 공식이기 때문입니다. 지우면 스핀축 관성이 1.64배 틀어집니다.
