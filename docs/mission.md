# Mission

- 임무: 특정 장소(패스트캠퍼스 10·11층) 내에서 VLM 기반 자율주행으로 방문객을
  강의장까지 안내
- 판정 시점: **2026-08-24(월) 시연** (`전체-작업계획.md:533` "월요일 시연")

> 아래에서 `전체-작업계획.md` · `계획-지도품질.md` · `잔여-공정.html` 은
> 저장소 밖 작업 노트(`~/Documents/종키/`)다. 저장소 안 근거는 파일:줄로 적었다.

## 1. 임무의 실제 범위

문서가 아니라 코드가 정하는 범위다.

| | 들어간다 | 근거 |
|---|---|---|
| 목적지 지정 | 터치스크린 버튼 · 음성(Whisper) · PTT | `guide_node.py::do_POST()`, `voice_node.py:113` |
| 목적지 해석 | 문자열 부분일치 → 실패 시 LLM | `guide_node.py::_resolve()`, `brain.py::resolve_destination()` |
| 주행 | 한 층 안에서 Nav2 `goToPose` | `guide_node.py::_drive_to()` → `BasicNavigator.goToPose()` |
| 앞장서 안내 | 뒤따라오는 사람 확인 · 뒤처지면 대기 | `guide_node.py::_wait_for_follower()` |
| 돌발상황 | 정체 6초 후 VLM 한 장 판단 | `guide_node.py::_guide_loop()`, `brain.py::judge_obstacle()` |
| 음성 안내 | piper 오프라인 TTS | `speech.py` |
| **층 전환** | **판정 대상 아님.** 코드가 2026-08-20 저녁에 들어왔으나 미커밋·실차 0회 | `docs/trace.md` 5번 홉 |
| **다중 로봇 · 관제** | **안 들어간다 — `fleet/guide_vda5050`·`guide_rmf`·`comms/` 가 README 3줄** | `docs/adr/001-vda5050.md`, `002-zenoh.md` |

즉 **시연 임무는 "한 층 안에서 등록된 강의장 한 곳까지 안내" 한 건이다.**
10층→11층 시나리오는 이번 판정 대상이 아니다.

## 2. 성공 기준

측정 도구는 이미 있다. `/guide/status` 가 상태 전이와 남은 거리를 JSON 으로
계속 발행하므로(`guide_node.py::_publish_status()` · `GuideState.snapshot()`) 시연 중 `ros2 bag record
/guide/status /cmd_vel /odom /scan` 하나면 아래 대부분이 사후에 재생된다.

| # | 기준 | 목표 | 재는 법 | 근거 |
|---|---|---|---|---|
| M1 | **목적지 도착률** | 20회 중 **18회 이상** `TaskResult.SUCCEEDED` | `/guide/status` 의 `status` 가 `arrived` 로 끝난 횟수 | 시행 횟수는 `collaboration.md:74` G7 의 "실물 임무 20회 시행" |
| M2 | **도착 정밀도** | xy ≤ **0.05 m**, yaw ≤ **0.08 rad** | 별도 측정 불필요 — Nav2 goal checker 를 통과해야 `SUCCEEDED` 가 나온다 | `nav2_params.yaml:97-98` |
| M3 | **안내 완료 시간** | 대기 구간을 뺀 순주행 시간이 **경로길이 ÷ 0.20 m/s** 이내 | `/guide/status` 의 `distance` 초기값과 `arrived` 시각 | RPP `desired_linear_vel` 0.30(`nav2_params.yaml:104`)에서 곡률·코스트 규제(`:116-119`)로 깎이는 몫을 감안한 **잠정값.** 첫 3회 시행으로 교체할 것 |
| M4 | **라이다 가시 장애물 충돌** | **0건** | 육안 + `/scan` 최소거리 이력 | 아래 3절 |
| M5 | **스캔 평면 아래 장애물** | **충돌 0건을 기준으로 쓰지 않는다** — 아래 3절의 통제 조건 충족 여부로 판정 | 사전 체크리스트 + 사고 시 별도 기록 | 아래 3절 |
| M6 | **사람 추종** | 4초 이상 뒤처지면 정지·대기, 60초 안에 재개 또는 정상 종료 | `/guide/status` 의 `waiting` 전이 · `follower_m` | `guide_node.py::_wait_for_follower()` 의 `LOST_LIMIT` 60초, `::_drive_to()` 의 `LOST_AFTER` 4초 · `TOO_FAR_M` 4 m |
| M7 | **사람 개입** | 20회 중 **0회** — 수동 조작·재부팅·RViz `2D Pose Estimate` 없이 | 시연 기록 | 초기 위치를 UI 에서 잡을 수 있게 됐다(`guide_node.py::set_start()`) |
| M8 | **미등록 질의 거절** | 오출발 **0건** — 목록에 없는 곳을 말하면 반드시 거절 | 의도적 미등록 발화 5회 | `guide_node.py::start_guiding()` 의 미등록 거절, LLM 응답도 목록 대조로 거른다(`brain.py::resolve_destination() 의 목록 대조`) |
| M9 | **음성 인식** | 등록 목적지 발화 10회 중 **8회** 매칭 | `voice_node.py` 로그의 `[들림]`/`[목적지]` | Whisper `tiny` 온보드, 부분일치(`voice_node.py:117-127`) |

M9 는 **부가 기준이다.** 음성이 없어도 버튼 UI 와 주행은 그대로 돈다
(`jongky_guide/README.md:63-64`). M1~M8 을 못 넘기면 M9 를 손댈 때가 아니다.

## 3. "충돌 0건" 을 쓸 때의 단서 — 라이다가 못 보는 높이가 있다

**Nav2 코스트맵의 관측원은 `/scan` 하나뿐이다**(`nav2_params.yaml:210-220`,
`:247-257`). 뎁스도 ToF 도 안 들어간다. 그리고 그 `/scan` 은 바닥에서
**0.21925 m 높이의 한 평면**이다(`jongky.urdf.xacro:148`,
`jongky_description/HANDOVER.md:119`).

그래서 로봇이 못 보는 것이 실제로 있다.

| 못 보는 것 | 왜 |
|---|---|
| 가방 · 케이블 · 납작한 상자 | 0.219 m 보다 낮으면 **반사가 아예 없다** (`전체-작업계획.md:358`) |
| 카트 · 책상 | 다리만 잡히고 상판 폭을 놓친다 (`전체-작업계획.md:361`) |
| 열린 사물함 문 · 떨어진 물건 | 같은 이유 |

**따라서 "충돌 0건" 을 단일 기준으로 쓰면 안 된다.** 이 기준은 로봇이 볼 수
있는 것에 대해서만 의미가 있다. 두 갈래로 나눈다.

**M4 — 라이다 평면에 걸리는 장애물: 충돌 0건이 정당한 기준이다.**
`inflation_radius` 0.30 · 내접 반경 0.085 m(풋프린트 220×170 mm,
`nav2_params.yaml:203`, `jongky_navigation/README.md:10`) 기준으로,
복도가 가장 좁은 사물함 구간 1.20 m 에서도 **중앙 0.60 m 가 비용 0 인
자유 대역**이다 (개방 구간 1.68~1.70 m 에서는 1.09 m).
파라미터를 건드릴 필요가 없다 — `계획-지도품질.md` 0절, `전체-작업계획.md:261`.

**M5 — 스캔 평면 아래 장애물: 충돌 0건을 로봇의 성적으로 세지 않는다.**
로봇에게 감지 수단이 없는 것을 성공 기준으로 걸면 기준이 운(복도 상태)을
재게 된다. 대신 **통제 조건**으로 판정한다.

- [ ] 시연 직전 주행 구간 바닥 정리 — 가방·케이블·박스·카트를 치운다
- [ ] 인솔자 1인이 로봇 옆에서 정지 가능 거리를 유지한다
- [ ] 그럼에도 충돌이 나면 **"M5 미달" 이 아니라 "통제 실패" 로 따로 기록**하고,
      그 물건의 높이를 재서 남긴다 (뎁스·ToF 도입 근거가 된다)

VLM 이 이 공백을 메워 주지 않는다. `brain.py` 는 **이미 멈춘 뒤에** 부르는
이벤트형 판단이고(`brain.py 머리말 [지연]`, `guide_node.py::_drive_to()` 의 `STUCK_AFTER` 6초), 정체 판정에
6초가 필요하다. 낮은 장애물은 로봇을 멈춰 세우지 못하므로 애초에 트리거가
안 걸린다.

## 4. 기준을 재기 전에 성립해야 하는 것

아래가 안 되어 있으면 위 숫자는 잴 수 없거나 의미가 없다. **전부 미완이다.**

| | 상태 | 근거 |
|---|---|---|
| `jongky_guide` 1회 실행 | ❌ **한 번도 빌드·실행된 적 없다** | `README.md:52-53`, `전체-작업계획.md` A1e |
| 지도 스케일 실측 ±2% | ❌ 기준선 실측 미완(현장 30초) | `계획-지도품질.md:20`, `전체-작업계획.md` A5 |
| waypoint 정리 | ❌ 저장키가 `w` 라 눌린 채 들어간 무효 항목이 있다 | `전체-작업계획.md` A2, `잔여-공정.html` N4 |
| 10층 지도 확정 | ❌ | `전체-작업계획.md` A3 |
| 후면 탐지 서비스 기동 | 컨테이너 밖 호스트에서 따로 띄워야 한다 | `follow_service.py 머리말 [왜 컨테이너가 아니라 호스트인가]` |
| 배터리 잔량 | ❌ 토픽이 없다 — 장시간 시연에서 남은 시간을 모른다 | `jongky_hardware/README.md:162-165` |

## 5. 성공 기준에서 **빼는** 것 — 지금 잴 수 없는 것들

그럴듯한 기준을 적어 두고 못 재는 것보다, 비었다고 적는 편이 낫다.

| 흔히 넣는 기준 | 왜 지금은 못 쓰나 |
|---|---|
| 층 전환 성공률 | 코드가 **오늘 들어왔지만** 미커밋·실차 0회다. 시연까지 나흘에 이걸 판정 기준으로 걸면 M1~M8 을 못 잰다 |
| 다중 로봇 배차 · 관제 대시보드 | `fleet/*`·`comms/*` 가 전부 README 3줄 |
| 학습 정책(DreamerV3) 주행 성능 | **학습을 아직 안 돌렸다** (`README.md:56`). Nav2 가 baseline 으로 남는다 (`전체-작업계획.md` 8절) |
| 뎁스 기반 회피 | 아스트라 최소거리 실측 미완, 코스트맵에 안 들어감 |
| VLM 판단 정확도 | 판단이 이벤트형이라 시연 한 판에 몇 번 안 걸린다. 표본이 안 모인다 |
| 통신 지연(Zenoh) | 브리지가 없다. 지금 로봇 밖으로 나가는 건 HTTP 두 갈래뿐 (`docs/interfaces.md`) |
