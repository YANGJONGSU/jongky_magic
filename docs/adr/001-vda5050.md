# ADR 001: VDA5050 채택

- **Status**: **미결 (Proposed). 구현 0건.**
- **Date**: 문서화 2026-08-20

> 이 ADR 은 "결정을 기록한 문서" 가 아니라 **"결정이 아직 안 내려졌음을
> 기록한 문서"** 다. 그렇게 적는 것이 비어 있는 칸을 그럴듯한 산문으로
> 덮는 것보다 정확하다.

## Context

계획 단계에서 `fleet/guide_vda5050` 을 "VDA5050 v3.0 어댑터 (MQTT/JSON)" 로
잡았고(`fleet/guide_vda5050/README.md:3`), 게이트 G4 의 통과 조건을
"VDA5050 어댑터 + Open-RMF → 외부 대시보드에 로봇이 잡힘" 으로 적었다
(`collaboration.md:61`).

## Decision

**아직 없다.** 2026-08-20 확인 기준:

| | |
|---|---|
| VDA5050 코드 | **0건** |
| MQTT 클라이언트 · `paho` 의존성 | **0건** |
| order/state JSON 스키마 | **0건** |
| `fleet/guide_vda5050/` 의 내용물 | README 3줄이 전부 |
| VDA5050 을 왜 골랐는지, 무엇과 비교했는지 | 저장소 어디에도 없다. **확인 안 됨** |

지금 실제로 도는 목표 전달 경로는 **Nav2 액션 직결**이다 —
`BasicNavigator.goToPose()` (`guide_node.py::_drive_to()`). 관제·플릿 계층을 거치지
않는다. `docs/trace.md` 4번 홉 참조.

## Consequences

- `docs/trace.md` 의 4번 홉에 VDA5050 자리가 **비어 있다.** 표에 그렇게 적혀 있다
- `fleet/guide_mission`·`fleet/guide_rmf` 도 같이 비어 있다. 셋의 선행 조건은
  `interfaces/guide_interfaces` 인데 그쪽도 README 3줄이다
  (`전체-작업계획.md` D절, 작업 노트)
- **2026-08-24 시연 판정 대상이 아니다** — `docs/mission.md` 5절
- 로봇이 한 대뿐인 동안은 이 계층이 없어도 임무가 성립한다.
  스코프를 깎으라는 제안이 이미 문서에 있다(`collaboration.md:93`)

## 다음에 이 문서를 채울 사람에게

결정을 쓰기 전에 최소한 이 셋에 답이 있어야 한다.

1. **왜 VDA5050 인가** — Open-RMF fleet adapter 만으로 안 되는 이유는?
   둘 다 잡아 둔 상태라 역할 분담이 불분명하다
2. **로봇 한 대에 필요한가** — 필요해지는 대수 기준을 적을 것
3. **MQTT 브로커를 어디에 두나** — 건물 WiFi 가 층마다 서브넷이 갈린다
   (`jongky_bringup/README.md 의 "현장 맵핑 절차" 절`). 이게 [adr/002](002-zenoh.md) 와 같은 문제다
